## 3. 관점별 종합 평가

### 디자이너 관점 (2/5 ~ 4/5)

- **강점**: 시각적 위계(4/5), 정보 밀도 적절, tabular-nums/keep-all 등 세부 배려
- **약점**: 디자인 시스템 일관성(2/5), 아이콘 품질(2/5), 위젯-메인 일관성(2/5), 접근성(2/5)
- **핵심 메시지**: "구조는 잘 잡혀 있지만, 디자인 시스템이 형식적" — 토큰은 정의되어 있으나 실제 사용은 하드코딩, 복숭아+초록 두 테마가 혼재

### 프로그래머 관점 (구조 4/5, 안정성 2.5/5)

- **강점**: IPC 설계(단일 커맨드+선택 리프레시), Mutex poisoning 복구, 리소스 정리, 의존성 최신
- **약점**: 2개 실제 버그(크래시, 속도 오류), async 블로킹, 테스트 전무, 빌드 산출물 커밋
- **핵심 메시지**: "규모 대비 구조는 깔끔하지만, 2개의 사용자 체감 버그와 아키텍처적 취약점(블로킹)이 있다"

### UX 전문가 관점 (2/5 ~ 4/5)

- **강점**: 정보 설계(4/5), 레이아웃·DPI 대응, 경계 상태(75/90%) 색상 피드백
- **약점**: 발견성(2/5), 일관성(2/5), 에러 리커버리(2/5), 학습 곡선(2/5)
- **핵심 메시지**: "데이터는 잘 보여주지만, 상태(로딩/에러/stale)를 커뮤니케이션하지 못하고, 숨겨진 기능이 많다"

## 4. 권장 개선 로드맵

### Phase 1 — 즉시 (v0.8.6, 안정성)

1. 싱글인스턴스 콜백 `expect` 제거 → `if let Some` + 메인 창 focus
2. 네트워크 속도: `last_refresh: Instant` 추가, 실제 경과 시간으로 계산
3. GPU `Option<f64>` → UI "—" 표시
4. 위젯 ✕ → 위젯만 hide, 앱 종료는 메인 창 ✕로만

### Phase 2 — 단기 (v0.8.7, UX/접근성)

5. 테마 토글을 전용 아이콘 버튼으로 분리 + aria-label + 키보드
2. 접기/펼치기 `<button>` + `aria-expanded` + `onKeyDown`
3. `:focus-visible` 포커스 링 복원
4. IPC 실패 시 "갱신 실패" 배지 + 마지막 갱신 시각
5. 메인 창 최초 로딩 스켈레톤
6. RAM 정리 토스트: 창 내부 배치 + 한국어

### Phase 3 — 중기 (v0.9.0, 디자인 시스템)
 1. 브랜드 컬러 1종 확정 → secondary/glow/hover 파생
 2. 다크 모드 프로그레스 트랙 토큰화
 3. 업데이트 알림 디버그 색상 제거
 4. 이모지 → SVG 아이콘 세트 (Lucide/Tabler)
 5. 위젯-메인 디자인 토큰 공유 + 위젯 라이트 모드
 6. 데드 CSS/토큰 제거, 타이포/스페이싱 스케일 확립
 7. 브랜딩 통일 (Sys4, lang="ko", 파비콘)

### Phase 4 — 장기 (v1.0, 기능/확장)
 1. 시스템 트레이 + 단축키
 2. 접기 상태·위젯 위치 영속화 (tauri-plugin-store)
 3. 폴링 로직 `useSystemResources` 훅 추출
 4. async → `spawn_blocking` 또는 동기 커맨드
 5. 테스트 도입 (Rust 단위 + JS vitest)
 6. 빌드 산출물 저장소 제거, GitHub Releases로 관리
 7. About/도움말, 자동시작 UI, `prefers-reduced-motion`

## 5. 3관점 리뷰 정례화 프로세스 (3Eyes Review)

### 원칙

1. **릴리스마다 수행**: 버전 태그(vX.Y.Z) 확정 후, 릴리스 노트 작성 전에 3관점 리뷰를 수행한다.
2. **관점 분리 위임**:
   - **디자이너** (architect 모드): 디자인 시스템, 색상/타이포/스페이싱, 접근성, 위젯-메인 일관성
   - **프로그래머** (code 모드): Rust/React 코드 품질, 버그, 아키텍처, 의존성, 테스트, 배포
   - **UX 전문가** (ask 모드): 사용자 플로우, 피드백/상태, 발견성, 에러 리커버리, Windows 관습
3. **교차 분석 필수**: 2개 이상 관점에서 공통으로 지적된 항목은 P0/P1로 격상한다.
4. **리뷰 문서 규격**:
   - 파일명: `3eyes_review_MMDD.md` (리뷰일 기준)
   - 구조: 1) 관점별 핵심 요약 2) 교차 분석(우선순위별) 3) 관점별 종합 평가 4) 개선 로드맵
   - 버그 항목은 반드시 **파일:라인 + 재현 조건**을 포함한다.
   - "만점/과대평가" 방지: 버그와 개선 제안을 분리하여, 버그는 재현 단계를 포함해야 한다.
5. **로드맵 추적**: Phase별 항목을 `update_X.Y.Z.md` 릴리스 노트에 반영하여 클로즈링한다.
